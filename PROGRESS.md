## 2. Toolchain & build system

- **Xcode 26.6**, **Swift 6.3** compiler. Project pins **Swift language mode 5.9**
  (`SWIFT_VERSION: "5.9"` in `project.yml`), so Swift 6 strict-concurrency issues are
  warnings, not errors. Builds clean today.
- **XcodeGen 2.44.1** generates `SendOnly.xcodeproj` from `project.yml`.
  Installed at `~/.local/bin/xcodegen`.
- Deployment targets: **macOS 14.0**, **iOS 17.0**.

### Regenerate + build (macOS)

```bash
cd ~/SendOnly
xcodegen generate          # only needed after editing project.yml
open SendOnly.xcodeproj     # then ⌘R in Xcode

# …or fully from the command line:
xcodebuild -project SendOnly.xcodeproj -scheme SendOnly \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO build
```

The built app lands at `build/DerivedData/Build/Products/Debug/Pigeon Mail.app`.

## 5. Authentication / Google Cloud (READ THIS)

- **OAuth 2.0 + PKCE**, loopback redirect `http://127.0.0.1:8089`.
- **Scopes requested** (all *sensitive*, none *restricted*):
  `gmail.send`, `gmail.compose`, `contacts.readonly`, `directory.readonly`,
  `userinfo.email`.
- Tokens stored in the **Keychain** (`KeychainService`). Client ID/secret entered
  in Settings.

### The weekly sign-in issue (7-day expiry)
The OAuth consent screen is in **"Testing"** publishing status. Google expires
refresh tokens for Testing-mode apps after **7 days**, which is why sending later
fails with `invalid_grant` / "Token exchange failed: Status 400".

- **Symptom handled:** as of 2026-07-12, a refresh that returns `invalid_grant`
  now clears the dead tokens and shows *"Your session expired. Please sign in
  again to keep sending."* instead of a raw 400 dialog. Fix: sign out → sign in.
- **Permanent fix (free):** In Google Cloud Console → OAuth consent screen (newer:
  *Google Auth Platform → Audience*) → **Publish app / push to production**. Moving
  out of Testing removes the 7-day expiry. No cost. Verification is **not** required
  (an unverified production app works for you + up to 100 users, with a one-time
  "unverified app" warning at sign-in). Because scopes are *sensitive* not
  *restricted*, even full verification would **not** incur the paid CASA assessment.
